AI Front Desk Helper — Booking API Integration Guide

Version 1.0 · For developers and CRM/platform integrators

Overview

This guide describes how to integrate with the AI Front Desk Helper Booking API. It lets an external system — a CRM, a partner platform, or an AI agent — check a business's open appointment slots and create real bookings on that business's calendar.

A booking created through this API is a real booking. It is identical to one created by the business's own AI receptionist: it reserves the time slot, creates the customer record, sends the customer a confirmation by text and email, and adds the appointment to the business's calendar. There is no separate "API booking" that behaves differently — the appointment lands exactly where the business already manages their work.

There are two ways to integrate, and they expose the same capabilities:

  • REST API — standard HTTPS requests. Best for most CRM and backend integrations.
  • MCP Server — a Model Context Protocol endpoint for AI agent platforms that speak MCP. Best when an AI assistant needs to discover and call booking as a tool.

Both are backed by the same booking system. Pick whichever fits your platform; you do not need both.

Before you start: what you need

To integrate, you need two values, both available from the business's AI Front Desk Helper dashboard:

Value What it is Where it's used
Business ID A unique identifier for the business (a UUID). In the URL path of every request.
API Key A secret key that authorizes booking creation for this business. In the request headers when creating a booking.

Keep the API Key secret. It authorizes the creation of real appointments and the sending of real messages to customers. Treat it like a password — store it server-side, never expose it in client-side code, browser apps, or public repositories.

Throughout this guide, replace {BUSINESS_ID} with the business's ID and {API_KEY} with their key.

The base URL for all requests is:

https://api.aifrontdeskhelper.com

Authentication

Authentication uses the business's API Key, supplied in the request headers. Two header formats are accepted — use whichever your platform prefers:

Authorization: Bearer {API_KEY}

or

x-api-key: {API_KEY}

Not every endpoint requires the key:

  • Checking availability is public. It returns only open time slots — nothing sensitive — so no key is required to read availability.
  • Creating a booking requires the key. It writes data and sends real messages to a customer, so it must be authorized.

REST API

1. Check availability

Returns the open appointment slots for a business.

GET /api/v1/availability/{BUSINESS_ID}

Authentication: None required (public).

Query parameters

Parameter Required Description
date Optional A specific day to check, formatted YYYY-MM-DD.
duration Optional Appointment length in minutes. Defaults to 60.

Behavior:

  • If you provide date, the response returns that single day's open slots.
  • If you omit date, the API scans upcoming days and returns the next several days (up to 7) that have openings — useful for "what's open this week" without knowing a specific date.

Example — a specific day

curl "https://api.aifrontdeskhelper.com/api/v1/availability/{BUSINESS_ID}?date=2026-07-15&duration=60"

Response (200 OK):

{
  "ok": true,
  "tenant": { "id": "{BUSINESS_ID}", "name": "Example Painting Co" },
  "date": "2026-07-15",
  "duration_minutes": 60,
  "slots": [
    { "value": "09:00:00", "time": "9:00 AM" },
    { "value": "13:00:00", "time": "1:00 PM" },
    { "value": "15:00:00", "time": "3:00 PM" }
  ]
}

Each slot has two fields:

  • value — the machine value (e.g. "09:00:00"). This is what you pass to the booking endpoint.
  • time — a human-friendly label (e.g. "9:00 AM") for display to a person.

Example — scan upcoming days

curl "https://api.aifrontdeskhelper.com/api/v1/availability/{BUSINESS_ID}"

Response (200 OK):

{
  "ok": true,
  "tenant": { "id": "{BUSINESS_ID}", "name": "Example Painting Co" },
  "duration_minutes": 60,
  "days": [
    {
      "date": "2026-07-15",
      "slots": [
        { "value": "09:00:00", "time": "9:00 AM" },
        { "value": "13:00:00", "time": "1:00 PM" }
      ]
    },
    {
      "date": "2026-07-16",
      "slots": [
        { "value": "10:00:00", "time": "10:00 AM" }
      ]
    }
  ]
}

2. Create a booking

Creates a real appointment.

POST /api/v1/booking/{BUSINESS_ID}

Authentication: Required — Authorization: Bearer {API_KEY} or x-api-key: {API_KEY}.

Request body (JSON)

Field Required Description
date Yes Appointment date, YYYY-MM-DD.
time Yes A slot value returned by the availability endpoint (e.g. "09:00:00").
duration_minutes Optional Appointment length. Defaults to 60.
contact.name Yes Customer's full name.
contact.phone Yes Customer's phone number.
contact.email Yes Customer's email address (must be valid).
contact.address Yes Service address (street, city, ZIP).
project_type Optional Type of project or service.
project_details Optional Additional detail about the job.
estimated_value Optional Estimated job value, in dollars. If supplied, the booking records this value.

All four contact fields are required — name, phone, email, and address. This is the same information the business collects on every booking through every channel, so the appointment is complete and actionable.

Example request

curl -X POST "https://api.aifrontdeskhelper.com/api/v1/booking/{BUSINESS_ID}" \
  -H "Authorization: Bearer {API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "date": "2026-07-15",
    "time": "09:00:00",
    "duration_minutes": 60,
    "contact": {
      "name": "Jordan Smith",
      "phone": "+14025551234",
      "email": "jordan@example.com",
      "address": "123 Main St, Omaha, NE 68102"
    },
    "project_type": "Interior painting",
    "project_details": "Two bedrooms and a hallway",
    "estimated_value": 2400
  }'

Success response (200 OK)

{
  "ok": true,
  "booking_id": "b1f2c3d4-...",
  "lead_id": "a9b8c7d6-...",
  "date": "2026-07-15",
  "time": "09:00:00",
  "tenant": { "id": "{BUSINESS_ID}", "name": "Example Painting Co" }
}

On success, the customer is automatically sent a confirmation, and the appointment appears on the business's calendar and dashboard. No further calls are needed.

Error handling (REST)

Every error response has the shape { "ok": false, "error": "<code>", ... }. The HTTP status tells you the category; the error code tells you the specific reason.

HTTP status error code Meaning & what to do
401 missing_api_key No key was provided on a booking request. Add the Authorization or x-api-key header.
403 invalid_api_key The key was provided but is wrong for this business. Check the key and Business ID match.
404 tenant_not_found The Business ID in the URL doesn't exist. Verify the ID.
409 slot_taken The slot was booked by someone else between your availability check and your booking call. Re-check availability and pick another slot.
422 validation_failed The request was understood but a field is missing or invalid. See the details array in the response.
422 day_closed The business is closed on that date. Choose another day.
422 outside_business_hours The time falls outside the business's working hours. Choose a time inside their hours.
422 invalid_datetime The date or time format wasn't understood. Check formatting.
502 availability_lookup_failed / booking_failed A temporary problem on our side. Retry after a short delay.

A note on slot_taken: availability can change between the moment you read it and the moment you book, because other channels (the business's website, phone, and text line) book the same calendar in real time. Always be ready to handle a 409 by re-fetching availability and offering the customer another slot.

Example validation error (422)

{
  "ok": false,
  "error": "validation_failed",
  "details": [
    "contact.email must be a valid email",
    "contact.address is required"
  ]
}

MCP Server

For AI agent platforms that speak the Model Context Protocol (MCP), the same booking capability is exposed as MCP tools. If you're building a standard CRM or backend integration, use the REST API above instead — this section is only for MCP-aware agents.

Connection

Each business has its own MCP endpoint:

POST /api/mcp/{BUSINESS_ID}

The protocol is MCP over JSON-RPC 2.0 on a single HTTP endpoint (Streamable HTTP, JSON responses). Supply the business's API Key at the transport layer using the Authorization: Bearer {API_KEY} or x-api-key header on the HTTP request — this keeps the key out of tool arguments and conversation context.

A quick health/discovery probe is available via GET on the same path:

curl "https://api.aifrontdeskhelper.com/api/mcp/{BUSINESS_ID}"

This returns the server info, protocol version, and the list of available tools.

Supported methods

The server implements the core MCP surface an agent needs to connect and call tools: initialize, notifications/initialized, tools/list, tools/call, and ping.

Tools

check_availability

Checks open appointment slots. Public (no key needed).

Argument Required Description
date Optional A specific day, YYYY-MM-DD. Omit to scan upcoming days.
duration_minutes Optional Appointment length. Defaults to 60.

Returns the same slot data as the REST availability endpoint — each slot has a value (pass to create_booking) and a human-friendly time.

create_booking

Creates a real appointment. Requires the API key on the connection.

Argument Required Description
date Yes Appointment date, YYYY-MM-DD.
time Yes A slot value from check_availability.
duration_minutes Optional Defaults to 60.
name Yes Customer full name.
phone Yes Customer phone number.
email Yes Customer email address.
address Yes Service address.
project_type Optional Type of project/service.
project_details Optional Extra detail about the job.
estimated_value Optional Estimated job value in dollars.

Example: tools/call

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "create_booking",
    "arguments": {
      "date": "2026-07-15",
      "time": "09:00:00",
      "name": "Jordan Smith",
      "phone": "+14025551234",
      "email": "jordan@example.com",
      "address": "123 Main St, Omaha, NE 68102",
      "project_type": "Interior painting"
    }
  }
}

Tool results are returned as MCP content blocks containing JSON text. A tool-level failure (e.g. a taken slot or a validation problem) is returned with isError: true and a JSON body describing the reason, using the same error codes as the REST API.

Integration checklist

A reliable integration follows this flow:

  1. Read availability with GET /api/v1/availability/{BUSINESS_ID} (or the check_availability tool). Show the customer the human-friendly time labels.
  2. Capture the four required contact fields — name, phone, email, and address. A booking can't be created without all four.
  3. Create the booking with the slot's value (not the display label) and the contact details, including the API key.
  4. Handle slot_taken (409) gracefully — re-fetch availability and offer another time. This is normal because the calendar is shared across all of the business's booking channels.
  5. On success, you're done — the confirmation to the customer and the calendar entry happen automatically.
